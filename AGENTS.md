# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

## Product decisions

- This is a personal macOS desktop dashboard built with Tauri, React, and TypeScript.
- `design/reference-dashboard.png` is the visual source of truth.
- Preserve the reference's dark graphite sidebar, light workspace, violet accent, today-focused work queue, seven-day schedule, and compact iteration-progress panel.
- The project scope selector is a single card control: its full rectangular area, including the summary line and whitespace, must open the project picker.
- Obsolete projects are disabled locally and remain recoverable; project management must never mutate or delete ptrace project data, and at least one project stays enabled.
- Real ptrace data always takes precedence over fictional values shown in the reference. Never present demo data as live data.
- The ptrace integration is read-only. Do not call mutating MCP tools.
- The breathing light for in-progress workitems is an out-of-flow decoration to the left of the workitem number; it must never shift the number, and all workitem numbers stay left-aligned. Center the breathing light vertically within each row on the workbench and all three workitem list pages. Use red dots with matching red halos for overdue workitems and violet for other in-progress workitems. The workbench overdue indicator is the red breathing light; horizontal dividers separate its rows.
- The app icon uses a fully opaque, edge-to-edge graphite-to-violet square master with a bold ivory tracking-path mark that subtly forms a `P`; do not pre-render a rounded squircle or transparent outer padding because macOS applies its own mask, and keep the mark text-free and legible at 16px.
- The Gantt chart is a dedicated read-only sidebar destination. It defaults to a four-week Monday-first timeline, supports week/month navigation, groups workitems by project and sprint, opens the existing workitem detail modal, and places workitems without both planned dates in an unscheduled section; it must never write schedule changes back to ptrace.
- Keep the Gantt week/month switch inside the chart content toolbar, beside the visible date range; the right side of that toolbar contains Today and previous/next navigation, and these controls must not occupy the shared top project header.
- On the “我的工单”, “我指派的”, and “别人指派的” pages, render every matching workitem in one continuous vertical list within the available viewport height. Status tabs and filters stay visible while only the workitem rows scroll. All rows use a flat surface with a single 1px divider between adjacent rows and a soft violet hover background. Keep row spacing compact and consistent across overdue and other workitems, using the red dot, deadline, and overdue label to indicate overdue work.
- On the workbench, the primary column and seven-day schedule should fill the available height below the shared header; do not cap them at a fixed maximum that leaves a large blank area at the bottom on tall windows.
- Keep scrollbars globally slim across the app: vertical scrollbars are 3px wide and horizontal scrollbars are 6px high, so they do not compete with page content.
- In workitem rows, clicking the workitem number block copies `<display number>(内部ID <internal ID>)` to the clipboard without opening details and briefly shows “已复制” in place of the internal ID; clicking anywhere else in the row continues to open the detail modal.
- With an existing ptrace session, automatically sync on weekdays at every quarter-hour from 09:00 through 18:00 inclusive; 18:00 is the final automatic sync of the day, while launch sync and manual refresh remain available.
- Normalize the ptrace workitem type label `Task` to the Chinese display label “任务” so it shares one filter option with workitems already labeled “任务”; never mutate the upstream ptrace value.
- Replace the workbench’s former seven-day agenda with a Monday-first monthly work calendar. Each date shows violet scheduled count and green completed count, uses only real `completedAt` values for completion, preserves workload warnings, and opens a date modal listing completed and scheduled workitems; selecting an item opens the existing workitem detail modal.
- The “别人指派的” sidebar destination shows workitems in the current project scope whose assignee is the selected identity and whose known creator is a different person; workitems without creator identity are excluded.
- With a selected ptrace identity, send a native macOS notification when a sync newly detects a workitem assigned to that identity by a known different creator. Compare against the previous real cache, exclude locally disabled projects, and treat the first sync without a real cache as the baseline without replaying historical assignments.
- On the “我的工单”, “别人指派的”, and “我指派的” pages, sort workitems by `createTime` descending so the newest creation appears first; place missing or invalid creation times last. Keep the workbench queue and calendar scheduled lists ordered by schedule.
- Workitem search uses case-insensitive partial matching across the displayed PT number, internal ID, and subject; the same search behavior applies to all three workitem list pages.
- The three workitem list pages share a parent-sprint filter based on each workitem's `sprintParentId` / `sprintParentName`, with all-parent and unset-parent options. Keep parent identities scoped by project, combine the filter with status, type, and search, and reset list scrolling to the top when the filters or project scope change. Status-tab counts reflect the parent-sprint, type, and search filters before status selection.
- The three workitem list pages also share a child-sprint filter based on workitems with a known parent and distinct `sprintId` / `sprintName`. Its options follow the selected parent sprint, include all-child and unset-child choices, and combine with the other list filters and status counts. Reset invalid child selections when the parent or project scope changes.
- Workitem details provide read-only Details, Comments, and Activity tabs. Load the full detail, threaded comments, activity history, and parent/child relationships on demand, with independent retry states and in-memory data. Keep list synchronization and its compact cache separate. Render current detail fields, all attachment links and metadata, and expandable source/extra fields; use verified names for activity values and preserve unknown values honestly. Show the pending detail load as a highlighted violet indicator immediately to the right of the workitem number in the header, using a fixed circular track with a centered rotating arc; clear it when the request settles and keep failure/retry feedback in the Details body. The header badge is the current workitem status indicator. The assignee field displays the person's name only. The labels row uses compact vertical spacing and aligns its caption, empty value, and tag text on the same baseline; multiple tags wrap naturally. The detail footer contains only creation and update timestamps.
- Render sanitized HTML and Markdown descriptions/comments with their tables, lists, code, and links. Show image attachments and content images in deduplicated galleries with thumbnails, enlarged previews, and retry controls. Accept HTTPS images from `ptrace-prod-uploads.ptrace.cfd`; render rich text and image elements separately. Escape closes the image preview first and returns focus to its thumbnail.
- The workbench primary region has a parent-iteration selector beside its heading, defaulting to an active iteration and offering an unset-iteration option. A selected iteration includes its direct workitems and all descendant iterations. The queue and personal metrics use the selected identity within that iteration; the progress panel uses the whole project iteration. Scope iteration identities by project, exclude disabled projects, and reset invalid selections after scope changes. The monthly calendar, other workitem pages, and synchronization keep their project-wide scope.
- PtraceDesk uses a Dock entry and a single main workbench window. Keep the macOS menu bar clear of PtraceDesk controls. Closing the main window hides its webview while scheduled sync and native assignment notifications continue; reopening from the Dock restores the workbench, and quitting the app ends background processing.
- The workbench task list groups all open workitems in the selected iteration into Today Plan, Overdue, and Later, with each item in one group. Today Plan includes non-overdue active items and items starting, ending, or scheduled across today. Show every overdue item; Later starts collapsed with its full count and an expand control. Keep the heading count aligned with Today Plan. Workbench rows use two-line titles, compact P1 badges, relative start/deadline times, and small due-state labels. Preserve the available-height container, internal scrolling, number copying, and out-of-flow breathing light; other workitem pages retain their existing row layout.
